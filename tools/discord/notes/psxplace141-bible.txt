Nothing to bind again: this is RIPPS2's page, writing your settings file. It has only run in the PCSX2 lab so far, not on a real PS2.

[LIST]
[*][B]A page like Settings[/B], with a tip on every row saying what it does and what it costs. The cursor stays on its row.
[*][B]Launch Keys[/B]: every button's name and ten paths, chosen with the Memory Files browser, typed, or one of BIBLE's commands, with arguments per path ([URL='https://github.com/akilluminati47/RIPPS2/blob/main/media/b141/launch-keys.mp4']watch[/URL]). Paths are written the way BIBLE reads them. The row tells you when your card's build cannot read a drive. The last path in the file stays, since a file with none sends BIBLE to its rescue mode.
[*][B]Sky Color[/B] (BIBLE_COLOR): follow the Color Theme, or keep any theme's sky by name.
[*][B]Stop Disc at Launch[/B] (DISC_STOP): Off skips the wait for the drive, about 3.3 s in a PCSX2 run, and a disc in the tray keeps spinning. A new install from Manage starts with it Off. A settings file already on your card is kept, so turn it Off yourself. It has not been timed on a real PS2 yet: if you do, post your numbers.
[*][B]The tray, Game ID rows and Boot Sound[/B] are on the page too. Read Console History is there as well, but BIBLE 3282396 reads that key and nothing uses it yet.
[*][B]A safer save[/B]: a temporary copy, read back whole, then it takes the real name. Your notes and every other line stay.
[/LIST]

[CENTER][IMG]https://raw.githubusercontent.com/akilluminati47/RIPPS2/main/media/b141/sky-splash.gif[/IMG][/CENTER]

[B]The boot sound, plainly:[/B] with Boot Sound On (fast), boot.adp sits beside BIBLE's settings on the card and RIPPS2 reads it before any drive starts: 0.26 s after the towers on a SCPH-39001 with an SD2PSX. BIBLE handing it over in memory has only passed in the lab so far, and does not happen on that console.

[B]Known:[/B] BIBLE 3282396 can stay on its splash for good when an AUTO path names a file that is not there on a drive it has to load a driver for (USB, MMCE, MX4SIO, HDD). It never reaches the next path. The lab saw this with mmce?:/APPS/RIPPS2.ELF and no device; the other cases come from reading the code. Going by the code, a button held at power on is not affected, so a button with a good path should get you past it. The lab cannot hold a button from power on, so that part has not been run. For now, give AUTO only paths that are really there on those drives. The fix is written and comes with the next BIBLE, after a re-sign.

Still wanted most: a genuine Sony memory card, a MemCard PRO 2, MX4SIO, the HDD build, slims, PAL and Japanese consoles. Tell us here or [URL='https://github.com/akilluminati47/RIPPS2/issues']open an issue[/URL].
